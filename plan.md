# План реализации tmdb_flutter

Перенос `tmdb_kmp` на Flutter. Источник поведения — KMP-приложение: каталог фильмов, сериалов и людей, карточка, персона, профиль с сессией TMDB и избранным.

Платформы первой версии: Android и iOS. Desktop собирается из того же `lib/` позже, отдельный UI-тулкит не заводится.

Файл обновляется по ходу работы: отмеченные пункты в чеклисте — уже сделанное в соответствующей ветке.

## Решения, которые не пересматриваем в ходе переноса

- Два слоя: общий `data/` и фичи с Notifier + виджетами. Use case только у логина и переключения избранного.
- Состояние и DI: Riverpod 3, `riverpod_generator`, `riverpod_lint`. Без Bloc, GetX, `get_it` и `flutter_hooks`.
- Навигация: `go_router` + `go_router_builder`. Переходы вызывает виджет, не Notifier.
- Сеть: Dio. JSON: `json_serializable`. Ошибки API: `TmdbException`, не обёртка `AppResult`.
- Ключ TMDB v4 передаётся заголовком `Authorization: Bearer`, как в KMP. Query-параметр `api_key` не используется. Имя define: `TMDB_ACCESS_TOKEN`.
- Сессия: `flutter_secure_storage`. Картинки: `cached_network_image`. Скелетоны: `skeletonizer`.
- Ключ TMDB: `--dart-define-from-file`, файл с ключом не коммитится.
- Один пакет, без melos и без pub-пакета на фичу.
- Язык интерфейса и запросов: `ru-RU`, как `language` в `TmdbApiClient`.
- Отдельный экран поиска из `feature/search` не переносим: поиск живёт в каталоге.
- Локальная БД не подключается, пока нет офлайн-сценария.
- `freezed` не подключаем: модели и state — обычные immutable-классы и sealed-типы Dart 3.

## Маршруты

| Экран | Путь |
|---|---|
| Каталог | `/` |
| Профиль, меню | `/profile` |
| Избранное | `/profile/favorites` |
| Фильм | `/movie/:id` |
| Сериал | `/tv/:id` |
| Персона | `/person/:id` |

Стек как в Decompose: каталог в корне, карточка и персона открываются поверх, профиль тоже поверх каталога. Повторный заход на тот же id не плодит дубликаты экрана. Редирект «избранное без сессии» смотрит сессию через `refreshListenable` и `ref.listen`, не через `ref.watch` внутри `redirect`.

## Этап 0. Каркас

- Создать приложение в текущем репозитории (`tmdb_flutter` сейчас пустой, кроме README).
- Подключить пакеты из стека и `very_good_analysis`.
- `bootstrap.dart`: `ProviderScope`, перехват ошибок старта, чтение ключа из `String.fromEnvironment`.
- Тема Material 3 и `ThemeExtension` под цвета TMDB. Атрибуция TMDB на каталоге, как `TmdbAttribution`.
- `GoRouter` с заглушками маршрутов.
- Dio: base URL, `api_key`, таймауты, разбор тела ошибки TMDB в `TmdbException`, лог только в debug.
- `SessionStorage` на `flutter_secure_storage` с методами read/write/clear для `session_id`, `account_id`, `username`.
- `config/dart_defines.json.example` без настоящего ключа. Пример команды запуска в README.

Готово, когда приложение открывается на `/` с пустым scaffold, Dio создаётся через провайдер, отсутствие ключа даёт понятную ошибку на старте, `flutter analyze` чистый.

## Этап 1. Данные каталога

Перенести контракты `MovieRepository`, `TvRepository`, `PersonRepository` без UI.

Эндпоинты первой волны, все с `language=ru-RU`:

- `genre/movie/list`, `genre/tv/list`
- `movie/popular`, `tv/popular`, `person/popular`
- `search/movie`, `search/tv`, `search/person` с `include_adult=false`
- `discover/movie`, `discover/tv` (`with_genres`, `sort_by`)
- `configuration` для базового URL картинок

Модели: `Movie`, `TvShow`, `Person`, `Genre`, `Paged<T>`, `ImageConfiguration`. DTO отдельно, маппинг внутри репозитория.

Сортировка как `MediaSortOption`: популярность, дата выхода (`primary_release_date.desc` / `first_air_date.desc`), оценка.

Тесты репозитория на фиктивном источнике: успешная страница, пустой поиск, ошибка HTTP с `status_message`.

Готово, когда репозитории покрыты unit-тестами и не зависят от виджетов.

## Этап 2. Каталог

`MediaNotifier` повторяет `MediaState`: тип контента, строка поиска, фильтры, жанры, элементы, первая загрузка, догрузка, ошибка, номер страницы, конец списка, id избранного, состояние сессии.

Поведение:

- Старт: популярное для выбранного типа и жанры фильмов/сериалов.
- Смена типа сбрасывает страницу и список.
- Поиск с debounce 400–500 мс. Пустая строка возвращает популярное. У людей фильтр жанра и сортировки нет.
- Активные фильтры уходят в discover, вместе с непустым запросом побеждает поиск (как в текущем сторе каталога; при расхождении сверить `MediaStoreFactory` до реализации).
- Догрузка не стартует повторно, пока идёт запрос или достигнут конец.
- Ошибка первой страницы — экран ошибки с повтором. Ошибка следующей страницы — сообщение под списком, уже загруженное остаётся.
- Сетка постеров, skeleton на первую загрузку, `memCacheWidth` у картинок.
- Тап ведёт на `/movie/:id`, `/tv/:id` или `/person/:id`. Иконка профиля ведёт на `/profile`.

Тест Notifier: первая страница, смена типа, debounce не дергает API на каждый символ, догрузка увеличивает page, конец списка останавливает запросы.

Готово, когда на устройстве листается каталог всех трёх типов, работают поиск и фильтры, ошибка сети не стирает уже показанный список.

## Этап 3. Карточка

`GET movie/{id}` и `GET tv/{id}` с `append_to_response=credits,videos,images,recommendations`.

`DetailsNotifier.family` по типу и id. State как `DetailsModel`: заголовок, описание, постер, фон, слоган, оценка, дата, хронометраж, жанры, статус, язык, бюджет и сборы для фильма, сезоны и серии для сериала, урезанный и полный состав, ключевой экипаж, видео, кадры, постеры, рекомендации, полноэкранная галерея, избранное.

Поведение:

- Повтор и кнопка назад.
- Состав раскрывается на месте, без нового маршрута.
- Тап по актёру открывает `/person/:id`.
- Тап по рекомендации открывает карточку того же типа.
- Ролик YouTube открывается снаружи через `url_launcher`.
- Галерея — локальный просмотр поверх карточки.
- Сердечко на этом этапе видно гостю как неактивное. Запись избранного включается на этапе 5. Контракт KMP: избранное только у фильмов (`AccountRepository` оперирует `movieId`).

Тест: успешная карточка фильма и сериала, ошибка с повтором, клик по рекомендации не теряет тип медиа.

Готово, когда обе карточки открываются из каталога и показывают блоки из `DetailsModel`.

## Этап 4. Персона

`GET person/{id}` с `append_to_response=combined_credits`.

State как `PersonModel`: имя, биография, фото, департамент, даты, место рождения, известен как, known for, роли актёра и экипажа с усечением и раскрытием.

Тап по кредиту открывает `/movie/:id` или `/tv/:id`.

Тест: разбор combined credits на актёрские и экипажные, раскрытие списка не ходит в сеть повторно.

Готово, когда из карточки и из каталога людей открывается персона, а из её фильмографии — карточка.

## Этап 5. Сессия и профиль

Клиент сессии по `TmdbSessionClient`:

- request token
- session по токену после подтверждения
- логин по логину и паролю
- аккаунт
- logout

`SessionRepository` хранит `Guest` или `Authenticated(accountId, username)` и поднимает состояние из secure storage на старте. Интерцептор Dio подставляет `session_id` только в запросы, которым он нужен.

Профиль:

- Гость: форма логина и ожидание подтверждения в браузере (`isAwaitingApproval`, подтвердить / отменить).
- Успех записывает сессию и закрывает сценарий входа.
- Выход чистит storage и список избранного.
- Меню как `ProfileMenuItem`. «Избранное» — маршрут `/profile/favorites` и `AccountRepository.getFavoriteMovies`. Остальные пункты открывают сайт TMDB `https://www.themoviedb.org/u/{username}/...`.
- Тап по избранному фильму открывает `/movie/:id`.
- На карточке фильма: прочитать `account_states`, переключить favorite. Гость уходит на `/profile`. Ошибка переключения не меняет предыдущий флаг.

Use case здесь оправданы: цепочка токен → сессия → аккаунт и команда «изменить избранное».

Тесты: восстановление сессии из storage, logout, отказ API на favorite не переворачивает флаг, гость не вызывает account endpoint.

Готово, когда логин, переживание перезапуска, избранное и выход проходят на устройстве с валидным ключом.

## Этап 6. Сборка поведения

- Сверка экранов с KMP: пустые состояния, тексты ошибок, атрибуция, сортировки, пункты меню.
- `ref.mounted` после каждого `await` в Notifier.
- Typed routes во всех `push`, без сырых строк путей в виджетах.
- README: как задать ключ, как запустить, какие сценарии считаются готовностью.
- Прогон `flutter analyze` и `flutter test`.

Готово, когда сценарии каталог → карточка → персона → назад, поиск, фильтр, логин → избранное → перезапуск → выход проходят вручную на Android.

## Вне первой версии

- Desktop и web.
- Офлайн-кэш и Drift.
- `l10n`, пока один язык.
- Пакетная нарезка фич.
- Избранное сериалов, если его нет в KMP.
- Отдельный модуль поиска.

## Порядок работ

Этапы идут по веткам из чеклиста сверху вниз. Каталог даёт первый видимый экран. Карточка и персона идут следом. Сессию не начинать, пока карточка фильма не открывается: избранное встраивается в уже готовый `DetailsNotifier`. Сверка с KMP входит в готовность, это не отдельная полировка «потом».

Коммиты и push делаются вручную, не из агента.
